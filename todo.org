** DONE Work on a better way to handle bootstrap python
    `bootstrap.sh` now reads `etc/koopa/vendor.json` directly (own JSON parse via
    whichever `python3` it finds, `sed` fallback if none exists) and routes every
    source download through it, honoring `vendor_first`/`vendor_only`. Fixed a
    live bug along the way: the koopa-mirror fallback URLs for openssl and python
    were 404ing (`src/openssl/`, `src/python/`) because they didn't match the
    app.json keys (`openssl3`, `python3.12`) that `koopa develop mirror-src`
    actually uploads under — `install_openssl`/`install_python` now derive the
    right name (python's tracks `.python-version` at runtime).

    Added a `http.remotes` map (host -> remote-proxy repo, exact then
    `.suffix` match) so a `vendor_only` network can resolve `github.com`,
    `koopa.acidgenomics.com`, etc. through a remote-proxy repository
    with zero pre-population — one entry proxying
    `koopa.acidgenomics.com` covers every source tarball koopa already
    mirrors there. `koopa.vendor.vendor_rewrite_url()` (Python) and
    `vendor_rewrite_url()` (the sh port in `bootstrap.sh`) implement this
    identically; `download_with_mirror()` in `koopa.download` folds it into
    the app-install path too, not just bootstrap.

    The `uv` fast path (prebuilt CPython, skips the ~10 min source compile)
    now takes `uv` from `PATH` under a vendor config instead of fetching it
    from GitHub, and derives `UV_PYTHON_INSTALL_MIRROR` from `remotes` so the
    CPython download itself can go through the mirror too (confirmed
    empirically that uv 0.12.3 honors that env var despite no `[env:]`
    annotation in `--help`). Known limitation: uv can't send the mirror's
    Bearer token, so an auth-required remote falls through to the (fully
    mirror-routable) source build automatically.

    `bin/koopa` also now checks `python3.12`/`python3` on `PATH`, not just
    `/usr/bin/python3` (mirrored in `koopa.system.find_system_python()` for
    `_update_venv()`), so an already-installed matching interpreter avoids
    bootstrapping at all.

    Verified: `sh -n` + `shellcheck` clean on both scripts; `ruff`/`ty`/`pyright`
    clean; full `pytest` suite (incl. new `test_bootstrap.py` anti-drift tests
    comparing the sh and Python vendor helpers byte-for-byte, plus a lock-out
    test for the mirror-name-vs-app.json-key bug); a real local HTTP server
    end-to-end run confirms a `vendor_only` bootstrap contacts only the
    mirror. Docs (`docs/installation.md`) rewritten and verified with a real
    `sphinx-build -W`.
