** DONE Usage of tilde character in org files for neovim causes weird incorrect esaping / highlighting problems.
    Root cause: Neovim's bundled syntax/org.vim defines the six inline
    emphasis regions (bold/italic/strikethrough/underline/verbatim/code) with
    'keepend' but no 'oneline'. Per ':help :syn-oneline', without 'oneline' an
    unclosed marker (a lone '~' in prose, e.g. "skips the ~10 min compile")
    highlights everything until the next stray marker or EOF instead of
    failing to open -- confirmed with a headless synID() sweep of this very
    file: 'orgItalic' was spanning lines 49-52 (opened by a stray '/' in
    'ruff format', closing on the next '/', swallowing the '** DONE'
    headline on line 51 along the way) and 'orgUnderline' similarly from
    '_revert_direnv_env()' on lines 41 and 47.

    Added opt/dotfiles/chezmoi/dot_config/nvim/after/syntax/org.vim, which
    clears and redefines all six regions with 'keepend oneline' and
    character classes based on org-emphasis-regexp-components. An unclosed
    marker now highlights nothing instead of running away. Deliberate
    tradeoff, recorded in the new koopa-neovim skill: real org syntax allows
    an emphasis span to wrap one newline, 'oneline' does not support that --
    a stray marker is far more common in freeform notes than a genuine
    multi-line span.

    Verified: re-ran the same synID() sweep against this file with the fix
    deployed -- lines 41, 47, and 49-52 report no orgUnderline/orgItalic;
    only orgHeadline, list markers, and genuinely paired emphasis survive. A
    literal '~10 min' also no longer needs the '<TILDE>' placeholder that had
    been standing in for it.
