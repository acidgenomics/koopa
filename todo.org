** TODO Confirm that we don't have Zsh passthrough weirdness with Ghostty terminal.
    The real cause: macOS's default shell is /bin/zsh. When you configure Ghostty with command = /koopa/bin/bash -il, Ghostty still auto-injects its shell integration using the POSIX injection mechanism — it starts bash in --posix mode with ENV=ghostty.bash. In that startup sequence, bash inherits the full macOS GUI environment.

    The key: macOS's BASH environment variable. macOS sets BASH=/bin/bash as a system environment variable. When the user's zsh session runs, zsh also sets BASH to its own path (/bin/zsh) as a compatibility variable — and exports it. When Ghostty's bash subprocess inherits this, BASH=/bin/zsh, so ${BASH##*/} = "zsh", causing all the zsh caches to load.

    The Ghostty config itself isn't wrong. The issue is that the caching code was using $BASH to detect the shell name — a variable that's writable/inheritable. The fix (hardcoding "bash" in all bash-specific activation files) is the correct solution. No changes needed to the Ghostty dotfiles config.
